Diseña un formulario para una plataforma universitaria

Un buen formulario no consiste solamente en colocar campos: debe facilitar que las personas proporcionen información correcta, comprender qué se les solicita y completar una tarea sin confusiones.

El reto

Imagina que una institución universitaria necesita habilitar un servicio digital para su comunidad. Tu tarea será proponer y construir la interfaz de un formulario web que permita recopilar la información necesaria para ese servicio.

Pregunta guía ¿Qué información necesita la institución y cuál es la manera más clara y sencilla de solicitarla al usuario?

1 Elige una situación

Selecciona uno de los siguientes escenarios o plantea uno equivalente, siempre que esté relacionado con una necesidad realista de la comunidad universitaria.

Registro a un taller o curso

Formulario para que estudiantes se inscriban a talleres, cursos, conferencias o actividades extracurriculares.

Solicitud de préstamo de equipo

Registro de solicitudes para utilizar proyectores, cámaras, laptops u otros recursos universitarios.

Reporte de problemas en instalaciones

Formulario para reportar fallas de iluminación, mobiliario, sanitarios, red o espacios comunes.

Convocatoria de servicio social

Registro de estudiantes interesados en participar en un proyecto o programa institucional.

Inscripción a una actividad deportiva o cultural

Recopilación de datos de participantes, disciplina o actividad de interés y disponibilidad.

Solicitud de apoyo o asesoría académica

Formulario para solicitar asesoría, tutoría o acompañamiento en una asignatura.

2 Define la información que necesitas

Antes de escribir código, identifica qué datos son necesarios para atender la solicitud. Organiza los campos en grupos lógicos y asigna un título a cada grupo.

  • Datos de identificación: nombre, matrícula, correo o teléfono, según el escenario.
  • Datos de la solicitud: tipo de servicio, actividad, categoría o motivo.
  • Detalles adicionales: descripción, comentarios, fecha o información complementaria.
  • Archivos de apoyo: fotografía, comprobante o documento, si el escenario lo requiere.

No solicites datos personales que no sean necesarios para el propósito del formulario.

3 Requisitos técnicos del formulario

Tu propuesta deberá incorporar, como mínimo, 8 tipos o elementos de los revisados en el ejemplo. Selecciona los que tengan sentido para tu escenario.

divFlexboxform fieldsetlegendlabel input textemailtel numberpasswordtextarea radiocheckboxselect optgroupdatalistfile requiredpatternmin / max maxlength
  • Utiliza fieldset y legend para separar secciones del formulario.
  • Asocia cada control con su etiqueta mediante label y el atributo for.
  • Utiliza controles adecuados al tipo de dato: por ejemplo, email para correo y number para cantidades.
  • Incluye al menos una validación HTML pertinente, como required, min, max, maxlength o pattern.
  • Organiza visualmente el formulario en una o dos columnas usando div y Flexbox. En pantallas pequeñas debe adaptarse a una columna.
  • Incluye botones para enviar y, si lo consideras útil, limpiar o cancelar.

4 Proceso de trabajo

  1. Analiza el escenario.
    Identifica quién utilizará el formulario, qué necesita solicitar y qué ocurrirá después del envío.
  2. Planea la estructura.
    Haz un boceto rápido de las secciones, el orden de los campos y la distribución visual.
  3. Construye el formulario.
    Implementa la estructura con HTML y aplica estilos CSS para mejorar la presentación.
  4. Prueba y corrige.
    Verifica que las etiquetas correspondan a sus campos, que las opciones funcionen y que las validaciones se activen.
  5. Presenta tu propuesta.
    Explica qué problema resuelve, por qué elegiste esos controles y cómo organizaste la interfaz.

5 Entregables

  • Archivo index.html con el formulario.
  • Al comienzo de su formulario agregué un párrafo explicando el escenario elegido y los controles HTML utilizados.
  • Captura de pantalla del formulario terminado.

Importante: en esta actividad se evaluará la interfaz y el comportamiento básico de los controles en el navegador. No es necesario conectar el formulario a una base de datos ni implementar un servidor.

6 Criterios de evaluación

Criterio Qué se revisará Valor
Organización y estructura Secciones claras, agrupación lógica de campos y uso correcto de elementos HTML. 25%
Uso de controles Selección pertinente y funcionamiento de los distintos tipos de campos. 25%
Diseño visual y usabilidad Distribución, legibilidad, alineación, consistencia y adaptación a pantallas pequeñas. 25%
Validación y pruebas Etiquetas asociadas, campos obligatorios y restricciones apropiadas. 15%
Justificación de la propuesta Explica el propósito del formulario y las decisiones de diseño. 10%

Antes de entregar, verifica

  • ¿El usuario entiende para qué sirve el formulario?
  • ¿Los campos están agrupados y ordenados de manera lógica?
  • ¿Cada campo tiene una etiqueta clara?
  • ¿Los controles elegidos corresponden a la información solicitada?
  • ¿El formulario se puede visualizar correctamente en una pantalla pequeña?
  • ¿Probaste qué sucede cuando dejas vacío un campo obligatorio?
